# دليل استكشاف الأعطال — NetDesk Lab

جميع الأمثلة تدريبية. الأداة تراجع الخطة؛ يتولى الفني التحقق من الحالة الفعلية وتوثيق الأدلة قبل أي تغيير.

## سيناريو: جهاز لا يصل إلى الطابعة

1. **حدد النطاق:** جهاز واحد أم عدة أجهزة؟ هل المشكلة بدأت بعد تغيير؟ هل الطابعة تعمل محليًا؟ وثّق الوقت والأثر وأسماء الأصول الافتراضية.
2. **افحص الطبقة الفيزيائية:** الطاقة والكابل وLink LED واتصال Wi-Fi عند استخدامه. حالة PoE مهمة للكاميرات التي تعتمد عليه.
3. **اجمع الإعدادات:** شغّل `ipconfig /all` على عميل Windows بإذن الجهة؛ سجّل عنوان IP والقناع والبوابة وخادم DHCP وDNS. لا تنشر مخرجات بيئة حقيقية.
4. **راجع الخطة:** حدّث نسخة محلية من JSON بالبيانات المصرح بها وشغّل الأداة. عالج ملاحظات الخطة المقترحة في بيئة تدريبية أو وفق إجراءات التغيير المعتمدة.
5. **تحقق ميدانيًا:** راجع Access VLAN وTrunk وSVI والتوجيه بين VLANs وفق تصميم البيئة، ثم ACL أو قواعد الجدار الناري ذات الصلة. اختلاف VLAN ليس بحد ذاته عطلًا إذا كان التوجيه والسياسات يسمحان بالاتصال.
6. **تحقق من الخدمة:** راجع عنوان منفذ الطابعة وقائمة الانتظار وخدمة الطباعة. إذا كانت المشكلة بالأسماء فقط، افحص DNS منفصلًا؛ الأداة لا تختبره.
7. **أعد الاختبار وأغلق البلاغ:** أثبت استعادة طباعة صفحة اختبار وسجّل السبب والإجراء والنتيجة أو ارفع البلاغ مع الأدلة.

## ربط النتائج بإجراء الفني

| النتيجة | تحقق يدوي قبل التصحيح | إجراء نموذجي |
|---|---|---|
| DUPLICATE_IP | إعدادات الجهازين وسجلات DHCP وARP | تعيين عنوان فريد وفق الخطة |
| STATIC_IN_DHCP | النطاق والاستثناءات والحجوزات الفعلية | استثناء معتمد أو نقل العنوان الثابت |
| GATEWAY_INVALID | قناع العميل وعنوان SVI/الراوتر | تصحيح البوابة أو الخطة بعد التحقق |
| SUBNET_OVERLAP | التصميم ووجود VRF منفصل من عدمه | إعادة تخطيط الشبكات في مجال التوجيه نفسه |
| UNKNOWN_VLAN | تعريف VLAN وتعيين المنفذ في السويتش | تصحيح السجل أو تعريف الشبكة المطلوبة |

وجود حجز أو استثناء فعلي لا يظهر في JSON قد يفسّر ملاحظة STATIC_IN_DHCP؛ لا تعتبر التقرير دليلًا على تعارض حي دون تحقق.

## نموذج بلاغ تدريبي

- رقم: LAB-001
- العرض: جهازان في Staff يستخدمان `192.168.10.10` وفق ملف الخطة.
- الأثر: خطر تعارض عناوين؛ لم يُقَس أثر اتصال فعلي.
- الدليل: DUPLICATE_IP في `examples/broken.json`.
- الإجراء المقترح: تغيير Staff-PC-02 إلى `192.168.10.11`، وحصر DHCP في `.100–.199`.
- التحقق: إعادة تدقيق الخطة، ثم اختبار الاتصال والخدمة في المختبر إذا كان متاحًا.

مرجع: [Microsoft ipconfig](https://learn.microsoft.com/en-gb/windows-server/administration/windows-commands/ipconfig).
