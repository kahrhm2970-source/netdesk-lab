# عرض المشروع في خمس دقائق

## 0:00–0:45 — المشكلة والحدود

«هذا مشروع تدريبي لمراجعة خطة IPv4 قبل تطبيقها، مناسب لفرع صغير فيه موظفون وطابعات وكاميرات. يتعامل مع خطة مكتوبة ولا يتصل بالأجهزة. جهّزت المشروع بمساعدة أدوات الذكاء الاصطناعي، وأتعلم تفسير قواعده ونتائجه.»

## 0:45–2:15 — مثال معطوب

شغّل `python netdesk.py examples/broken.json --out reports/broken`.
افتح `reports/broken/audit.html`. سترى 11 ملاحظة ضمن تسع فئات.

اشرح ثلاثًا:

1. جهازان في VLAN 10 يحملان العنوان نفسه. اقترح عنوانًا فريدًا.
2. بوابة الطابعات خارج شبكتها. راجع قناع الشبكة وعنوان الراوتر قبل التعديل.
3. شبكة Guest متداخلة مع Cameras في مجال توجيه واحد. راجع التصميم وأعد التخصيص.

## 2:15–3:00 — مثال سليم

شغّل `python netdesk.py examples/healthy.json --out reports/healthy`.
المتوقع PASS وصفر ملاحظات. وضّح أن شبكة Guest حُذفت من الخطة السليمة لأنها غير مستخدمة، وأن PASS لا يثبت الوصول الفعلي أو العزل الأمني.

## 3:00–4:00 — التحقق

شغّل `python -m unittest discover -s tests -v`.
اشرح اختبارًا واحدًا: عنوان Broadcast ليس عنوان جهاز صالحًا في هذا النموذج. ثم افتح اختبار HTML escaping ووضح لماذا لا ندرج اسم الموقع في HTML دون تهريب.

## 4:00–5:00 — الصلة بالدعم الفني

اعرض RUNBOOK_AR.md: جمع الأدلة، مراجعة الخطة، التحقق الميداني، ثم توثيق الحل. ناقش تطويرًا لاحقًا مثل دعم DHCP exclusions أو IPv6، دون الادعاء أنه موجود.

## أسئلة راجعها قبل المقابلة

- لماذا نعزل الطابعات والكاميرات في VLANs، وما دور التوجيه والسياسات بينهما؟
- ما الفرق بين Network address وBroadcast وUsable host؟
- لماذا قد يتعارض عنوان ثابت مع DHCP؟ ومتى يعالج الحجز أو الاستثناء ذلك؟
- لماذا لا تكفي مراجعة JSON للحكم على سلامة الشبكة؟
- ما الفرق بين خروج البرنامج بالقيم 0 و1 و2؟

مرجع تقني: [Python ipaddress](https://docs.python.org/3/library/ipaddress.html).
